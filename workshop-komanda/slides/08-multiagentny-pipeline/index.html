Кирпич · один агент
Один агент — это одно ТЗ
Роль — кто одной фразой
Задачи — 3–5 операций глаголами (вход → выход)
Инструменты — что вызывает: поиск, расчёт, документ
Память — что знает про компанию + история
Правила — 3–5 «если…, то…», включая «никогда»
Связи — откуда вход, куда выход и кому
Безопасность — где зовёт человека
Критерий готовности — 3–5 реальных кейсов
Большую задачу один агент не вытянет — собираем из таких ТЗ конвейер
Большая задача
Почему «спланируй и сделай» одним агентом разваливается

План текстом теряет важное

Роли планируют текстом, исполнитель читает текст — и выпадает доступ, связь со смежной системой, готовый кусок. Никто не написал явно — для следующего агента этого нет.
1Жёсткий бланк — план не текст, а форма с обязательными полями. Пустое поле = план не принят. Забыть пункт нельзя
2Независимый контролёр — план проверяет отдельный агент с чистого листа: он не планировал, читает только файлы и ищет дыры
3Каждому свой кусок — исполнителю даём не «всё подряд», а его срез: что делать + ровно нужные доступы, документы, части кода
Всё, что решено, — в файле. Чего нет в файле — не существует
Конвейер с контролем
Как это работает у меня — команда агентов
1Разведчик — до плана собирает доступы, документы, код, связи. Решение не придумывает
2Проектировщик — заполняет бланк плана; каждый блок ссылается на разведку
✓Контроль плана — новый агент с чистого листа. Принято → дальше · не принято → план на доработку
3Исполнители — каждому своё задание: задача + срез разведки + критерий. Запускаю по очереди, не сами
✓Контроль макета — для интерфейса: машинная сверка с эталоном (иконки, цвета), не «на глаз»
Контролёр — отдельный незаинтересованный агент. Дважды не принято подряд → стоп: задача сформулирована нечётко
